# QLabs QCar2 智能小车功能集成项目

---
重要提醒：该项目所有代码参数都是在个人PC上完成，由于QLabs平台仿真十分吃电脑配置和性能，不一样的电脑运行该项目会出现完全不一样的性能，需要自行修改匹配参数；建议运行时关闭其它软件。
---
本项目基于 Quanser 公司的 QLabs 虚拟仿真平台与 QCar2 智能小车模型，围绕自动驾驶小车的基础行驶能力进行开发与集成。当前已经实现的功能包括：

- 自主循路：基于前后摄像头的车道线识别与 PID 转向控制。
- 避障换道：在自主循路基础上加入障碍物识别、车道虚实线判断、五次多项式换道规划与 Stanley 横向控制。
- 侧方位停车：基于 QLabs 中的车辆位姿/GPS 类定位信息，使用状态机完成自动泊车。
- 自定义测试场景：包含基础侧方位停车场景，以及面向后续功能集成的公路、十字路口、红绿灯和停车道路组合场景。

项目目标不是只展示单个脚本，而是逐步把视觉感知、路径跟踪、避障决策、泊车控制和场景搭建组合成一个适合智能小车实验验证的 QLabs 工程。由于 QLabs 自带场景不完全适合当前功能集成测试，本项目额外搭建了可控道路、路口和停车区域，并自定义了黑色背景板红绿灯，避免官方黄色背景板对视觉识别造成明显干扰。

## 1. 项目结构

```text
QLabs_github/
├─ lane_following.py                 # 自主循路主程序
├─ polynomial_with_obstacle.py       # 视觉循路 + 障碍物检测 + 自动换道
├─ parallel_parking.py               # 侧方位停车主程序
├─ parallelparking_scene_builder.py  # 基础侧方位停车场景搭建与预览
├─ 官网教学案例/                     # Quanser 官方示例代码，适合入门学习
└─ 进阶场景集成/                     # 自定义公路、路口、红绿灯和停车区域组合场景
```

核心脚本建议按学习顺序阅读：

1. `官网教学案例/`：先熟悉 QLabs 中物体、摄像头、道路标识等基础 API。
2. `lane_following.py`：理解摄像头图像读取、车道线提取和循迹控制。
3. `polynomial_with_obstacle.py`：理解在循迹基础上如何加入障碍检测和换道状态机。
4. `parallelparking_scene_builder.py`：先查看侧方位停车场景如何生成。
5. `parallel_parking.py`：运行完整侧方位停车控制流程。
6. `进阶场景集成/`：查看更复杂的自定义道路、十字路口、红绿灯与停车区组合。

`进阶场景集成/` 目录下已经提供了单独的说明文档：`进阶场景集成/场景搭建说明.md`。该部分代码较独立，本文档只做整体介绍，具体参数和接口请优先阅读该目录内说明。

## 2. 功能说明

### 2.1 自主循路：lane_following.py

该脚本通过 QCar2 的前后 CSI 摄像头读取道路图像，并使用 OpenCV 提取车道线位置。程序会在图像中构建感兴趣区域 ROI，对白色车道线进行阈值过滤，然后在预设扫描带中寻找左右车道边缘。根据车道中心与图像中心的像素偏差，计算车辆横向误差，并通过 PID 控制得到转向角。

运行后可以看到两个 OpenCV 窗口：

- `Front Camera`：前视摄像头检测结果。
- `Rear Camera`：后视摄像头检测结果。

窗口中会显示车道线检测区域、扫描带、左右边缘点、目标中心点和误差值。车辆会以较低油门持续沿车道线行驶。

### 2.2 避障换道：polynomial_with_obstacle.py

该脚本是在自主循路基础上扩展的功能。除了车道线识别外，程序还会在前视图像中识别橙色或红色交通锥，并根据识别框位置估算障碍物距离。

主要逻辑包括：

- 使用 HSV 颜色阈值检测交通锥障碍物。
- 根据车道线连续性判断左右边界是实线还是虚线。
- 如果可变道一侧为虚线，则进入避障换道状态。
- 使用五次多项式生成平滑横向位移参考轨迹。
- 使用 Stanley 控制器跟踪换道轨迹。
- 换道完成后重新切回视觉循迹。
- 如果两侧均为实线且前方存在障碍物，则触发停车保护。

程序运行时会在图像窗口中显示：

- 车道线检测结果。
- 左右车道线类型记忆结果（实线/虚线）。
- 障碍物检测框与估算距离。
- 当前速度信息。

该脚本适合用来观察一个完整的“视觉感知 -> 障碍检测 -> 决策 -> 轨迹规划 -> 横向控制 -> 恢复循迹”流程。

### 2.3 侧方位停车：parallel_parking.py

该脚本面向侧方位停车实验。与前两个视觉项目不同，侧方位停车主要依赖 QLabs 中车辆的世界位姿信息进行状态判断。程序会搭建一段道路和右侧停车位，并通过状态机控制 QCar2 自动倒入车位。

当前停车流程可概括为五个阶段：

1. 右倒打死：车辆后退并向右切入车位。
2. 直线后退：保持姿态继续进入车位。
3. 左倒打死：反向修正车身姿态。
4. 前进微调：根据航向误差修正车身。
5. 停车保持：停止车辆，保持 Matplotlib 俯视图窗口。

脚本还会使用 Matplotlib 绘制俯视参考图，显示道路边界、停车位、车辆轮廓、车头方向和运动轨迹，便于观察每个阶段的姿态变化。

### 2.4 基础侧方位场景：parallelparking_scene_builder.py

该脚本主要用于单独构建和预览侧方位停车场景。它会在 QLabs 中绘制道路底面、车道边界、停车位边界和入口虚线，并生成一辆静止的 QCar2。同时，它会打开 Matplotlib 俯视图，帮助检查场景几何尺寸是否合理。

如果只是想确认停车场景是否搭建成功，可以先运行该文件，再运行完整停车控制程序。

### 2.5 官网教学案例

`官网教学案例/` 中的脚本来自 Quanser 官方示例，主要用于理解 QLabs 基础对象和 API 的使用方式，例如：

- 摄像头示例。
- 墙体与迷宫示例。
- 人物、斑马线、道路标识示例。
- 样条线和基础场景元素示例。

这些示例更适合作为入门参考，不是本项目功能集成的主入口。

### 2.6 进阶场景集成

`进阶场景集成/` 是本项目的自定义场景模块，用于解决 QLabs 现有场景不适合综合测试的问题。该目录包含：

- `road_scene.py`：生成连续公路、坡道、S 弯和标线。
- `intersection_scene.py`：生成十字路口、斑马线和自定义黑色背景板红绿灯。
- `paralleling_parking.py`：生成可拼接的侧方位停车道路区域。
- `scene_runner.py`：组合公路、路口和停车区，并持续更新红绿灯状态。

详细用法请阅读：`进阶场景集成/场景搭建说明.md`。

## 3. 环境准备

### 3.1 软件要求

运行本项目需要提前安装并配置以下环境：

- Windows 系统。
- Quanser Interactive Labs / QLabs。
- QCar2 相关 QLabs 资源与实时模型。
- Quanser Python API，包括 `qvl`、`pal` 等包。
- Python 3.x。
- 常用 Python 科学计算与图像处理库：`numpy`、`opencv-python`、`matplotlib`。

其中 `qvl`、`pal` 通常不是普通开源 pip 包，而是随 Quanser / QLabs / QCar 教学环境提供。若导入失败，请优先检查 Quanser 官方环境是否安装完整，以及当前 Python 解释器是否能访问 Quanser 提供的库。

### 3.2 Python 依赖

如果你的 Quanser 环境已经配置好，但缺少通用第三方库，可以尝试安装：

```powershell
pip install numpy opencv-python matplotlib
```

如果你使用的是学校或实验室提供的虚拟环境，请先激活对应环境后再安装依赖。不要随意切换 Python 解释器，否则可能出现 `qvl` 或 `pal` 无法导入的问题。

### 3.3 QLabs 启动要求

所有功能脚本运行前，都需要先启动 QLabs，并确保 Python 可以连接本地 QLabs 服务。

如果项目上级目录中存在 `OpenQLabs.bat`，可以先运行该批处理文件打开 QLabs。也可以手动启动 QLabs 软件并加载合适场景。

脚本内部通常会执行以下操作：

- 连接 `localhost` 上的 QLabs。
- 清理历史生成的车辆或场景对象。
- 生成 QCar2。
- 启动 QCAR2 实时模型。
- 将视角绑定到小车。

因此运行脚本前请确认 QLabs 已经打开，否则会出现连接失败提示。

## 5. 常见问题

### 5.1 无法连接 QLabs

请确认：

- QLabs 软件已经启动。
- 当前场景允许本地 Python API 连接。
- 脚本连接地址仍为 `localhost`。
- 没有其他异常进程占用或卡住 QLabs 实时模型。

### 5.2 导入 qvl、pal 失败

这通常说明当前 Python 环境没有配置 Quanser 相关库。请检查：

- 是否安装了 Quanser Interactive Labs / QCar 相关软件包。
- 是否使用了实验环境指定的 Python 解释器。
- VS Code 当前解释器是否与终端运行脚本时的解释器一致。

### 5.3 OpenCV 窗口按键没有反应

`cv2.waitKey` 需要图像窗口处于焦点状态。请先点击弹出的图像窗口，再按 `q` 或 `Esc`。

### 5.4 小车没有运动或运动异常

可以按以下顺序排查：

1. QLabs 是否已经启动并连接成功。
2. QCAR2 实时模型是否成功启动。
3. 脚本是否正确生成 `actorNumber=0` 的 QCar2。
4. 摄像头画面是否正常显示。
5. 车道线是否在 ROI 区域内被正确识别。
6. 场景坐标是否与脚本中初始位置匹配。

### 5.5 红绿灯影响视觉识别

官方文档中的红绿灯示例带有黄色背景板，可能会干扰颜色阈值识别。本项目在进阶场景中使用了自定义黑色背景板红绿灯，更接近真实道路设备，也能减少对红绿灯颜色识别和其他视觉任务的干扰。

### 5.6 上传 GitHub 时不建议提交的文件

建议不要提交 Python 缓存和本地临时文件，例如：

```text
__pycache__/
*.pyc
.venv/
.vscode/
```

如果后续要正式开源，建议新增 `.gitignore` 文件来统一排除这些内容。


```powershell

```
